# NH PLUG read adapter status — 2026-09-27

## Scope

- `src/pykbroker/brokers/nh.py` is a direct-import, domestic, read-only adapter.
- The factory does not register `nh`; no order submission or cancellation is implemented.
- `market="US"` is locked even though a separate official overseas specification exists.
- `virtual=True` selects the mock read host; token issuance always uses the live host.

## Sources

- Official common OpenAPI: https://www.nhplug.com/openapi-docs/common/openapi.json
- Official domestic OpenAPI: https://www.nhplug.com/openapi-docs/krstock/openapi.json
- Official overseas OpenAPI: https://www.nhplug.com/openapi-docs/gbstock/openapi.json
- Official guidance: https://www.nhplug.com/llms.txt
- Existing registration boundary: quantus-fastapi `quantus_backend/utils/nh_client.py`.

## Contracts

- `/oauth2/token` receives form-encoded appkey, appsecretkey, grant_type, and scope.
- The token is valid for `expires_in` seconds and can be supplied in `client_options`.
- An injected `token_cache` shares state; `token_state()` lets the caller persist it.
- Reads send Bearer authorization and x-client-id, never x-client-secret.
- The adapter sends an `Input_0` object for each domestic read.
- Quote: `/krstock/quote/v1/currentPrice`, with `market_cd` and `iem_cd`.
- Balance and holdings: `/krstock/inquiry/v1/balance`, `Output_0` and `Output_1`.
- Buyable shares: `/krstock/inquiry/v1/buyableQuantity`, cash and ordinary-price inputs.
- Sellable shares: `/krstock/inquiry/v1/sellableQuantity`, ordinary cash position.
- `/n2/acctinfo` verifies account ownership and type on the live host, including for mock accounts.
- Account types 01/02 use live; type 03 uses mock.
- Balance follows response `cts` and `cts_flag` through at most 100 pages; repeated keys fail closed and the final page supplies `tot_eal_amt`.
- Cash buyable quantity uses `csh_orr_pbl_qty` for `ost_dit_cd=1` and refuses a missing field.
- Reads share a per-credential four-per-second limiter, including continuation and per-symbol sellability calls.

## Error policy and evidence

- HTTP 200 alone is not a successful money read; the expected block and fields must exist.
- A valid `dca=0` with `orr_pbl_amt=0` is a zero balance, not a missing result.
- Known response codes and completion messages follow the existing fastapi classifier.
- Explicit unknown business codes fail; 429 never causes token issuance.
- A 401 can cause one token renewal and one read replay, if a secret is available.
- Vendor response bodies and credentials are excluded from exception messages.
- `tests/test_nh_read_contract.py` uses fake transport and no real credentials.
- No live account or order call was made; actual vendor row shapes remain unobserved.
