# Broker support matrix

2026-10-01 등록 구현 기준입니다. 이 작업의 검증은 전부 mock·합성 fixture에 의한 오프라인 계약 검사입니다. **실 API·모의계좌·실거래 검증은 수행하지 않았습니다.**

KIS는 정정·취소 가능 주문 목록을, Toss는 열린 주문 목록을 제공합니다. 이 목록에서 사라진 주문을 체결 완료로 추정하지 않습니다. DB 조회는 SDK가 반환한 연속 조회 페이지를 검증·병합합니다. DB의 잔량 0만으로 최종 상태를 확정하지 않습니다.

KIS/DB US 잔고의 주문 가능 현금은 계좌 유형별로 달라 `cash_provider` 주입을 요구합니다. US 매수·매도는 지정가만 노출합니다. 계좌에 없는 NXT·상품·시장 기능을 유추하지 않습니다.

## 키움 (2026-10-01)

`create_broker("kiwoom", ...)`은 기존 REST 어댑터를 저장 토큰·앱키로 만듭니다. 생성만으로 토큰을 발급하지 않습니다. 주문·취소 전송은 기존 `OrderSafety` 기본 dry-run으로 꺼져 있으며 이를 켜는 새 환경변수는 없습니다. `virtual=True`일 때 모의 호스트를 고릅니다. 직접 정정은 공통 SDK 계약에 없습니다. 가짜 정정 원장을 읽으면 완전 체결 외에는 원주문을 ‘모름’으로 남깁니다.

가격 부호 증거는 오프라인입니다. `+` 가격은 크기를 유지하고, `-` 가격은 시세·호가·상하한가·잔고·미체결 주문 모두 `SpecUnverifiedError`로 거부합니다. 음수 현금·수량은 계속 잘못된 응답입니다. 공식 샘플만으로 `-` 의미가 확정되지 않아 절댓값으로 추정하지 않습니다.

기존 `examples/kiwoom_mock_roundtrip.py`의 기본은 dry-run입니다. `--execute`여도 모의 키가 없거나 공백이면 ‘키 없음’, `missing_keys`, 종료코드 0으로 끝나며 클라이언트 생성도 없습니다. 이는 실행 생략이지 왕복 성공이 아닙니다. 주문·조회·취소 왕복은 가짜 응답으로 시험했습니다. 증권사 실제 호출은 하지 않았습니다. 모의 키 발급 뒤 실제 모의 왕복과 독립 검수가 필요합니다.

근거: [키움 검증 기록](status/2026-10-01-pack-kiwoom-bs07.md).

## LS (2026-10-01)

`brokers/ls.py`와 `create_broker("ls", ...)`에 등록되어 있으며, 기존 `experimental.ls`는 같은 모듈의 호환 경로입니다. 생성 시 명시적인 `base_url`을 가진 클라이언트가 필요합니다. 기본 클라이언트·키·요청 예산·코드 기본값은 없습니다.

**실 바인딩의 주문·취소는 계속 잠겨 있습니다.** `virtual`은 bool만 받으며 생성 직후와 요청 전에 호스트를 검사합니다. `LS_SPEC_VERIFIED=False`는 전체 주문 금지 스위치입니다. 이를 바꿔도 실 바인딩은 열리지 않습니다. 별도 모의 주소 계약은 **UNVERIFIED**로 비어 있어 `virtual=True` 생성도 거절됩니다. 모의 주소를 실 주소로 추정하지 않습니다.

시험에서는 가짜 모의 호스트와 `spec_verified=True`를 인스턴스별로 명시해 기존 안전 게이트를 검증합니다. 기본값은 `False`이며 다른 인스턴스에 전파되지 않습니다. 반환 주문의 `virtual`은 생성 때 검사한 바인딩을 따릅니다.

`t0425.qty/cheqty/cheprice`는 **UNVERIFIED(명세 미확인)**입니다. 잠금 중에는 `quantity`·`filled`·`fill_price`가 `None`, `status`는 `unknown`입니다. `cheprice`가 평균 체결가인지 확인되기 전에는 잠금을 바꿔도 `fill_price`를 채우지 않습니다. 실시간 미체결·주문 이력·모의계좌 지원은 선언하지 않습니다. 모든 LS fixture는 합성입니다.

## NH (2026-10-01)

`create_broker("nh", ...)`는 저장 토큰 또는 앱키·시크릿으로 생성합니다. 계좌 종류 `acct_type`은 모의 `03`, 실계좌 `01`/`02`를 명시해야 합니다. 생성 직후 주입 클라이언트의 호스트도 검사합니다. 모의 주문·취소와 계좌 조회는 moapi, 토큰·계좌 확인·시세·규칙표는 api 호스트를 씁니다. 시세 운영 전용은 공식 명세 표시이며 실제 API 응답 확인 전 **UNVERIFIED**입니다.

실계좌 주문·취소는 `allow_live_orders=False` 기본 잠금입니다. `OrderSafety`나 MCP 주문 한도만 켜도 NH 실주문은 열리지 않습니다. 명시 해제 인자는 주문번호·원장번호 연결 검증과 별도 승인 뒤에만 사용해야 하며, 해제 후에도 기존 안전 게이트를 거칩니다. 계좌 소유 확인(`verify_account`)의 필수 적용은 주문번호·원장번호 연결 검증 때 함께 다룹니다.

계좌 모드 `virtual`은 읽기 전용이며 생성 때 검사한 주문 호스트로 잠금과 주문 표시를 판정합니다. 읽기는 알려진 정상 코드와 필수 데이터 블록으로 판정하고 완료 실패 문구를 거부합니다. `13578` 응답의 블록 없는 보유·일별 주문 내역은 빈 목록이며 매도가능 수량은 0입니다. 현금 조회는 요약 블록이 필요합니다. 모르는 코드는 완료 문구가 있어도 거부합니다. 손상된 공유 토큰 만료는 무시하고 새 토큰으로 덮으며 더 최신인 공유 토큰은 보존·재사용합니다. HTTP 리다이렉트는 따라가지 않습니다. 주문 응답 `mkt:`와 원장 `itg:`의 연결은 아직 없어 주문 직후 상태는 모름입니다.

근거: [NH 현황 팩](status/2026-10-01-pack-nh.md), [공식 시세 필드 발췌](contracts/nh-current-price-fields.json). 실제 증권사 호출은 수행하지 않았습니다.

## KB (2026-10-08)

`brokers.kb.KB`는 등록된 KR/US REST 어댑터입니다. 쓰기는 `writes_enabled=False`와 기존 `OrderSafety`로 기본 잠금이며 모의 API는 없습니다. 생성은 저장 토큰을 사용하고, `KB.issue_token(app_key=..., secret_key=...)`를 명시적으로 호출할 때만 Client Credentials 토큰을 발급합니다. 공식 `token.json`과 GitHub Python 예제의 `dataHeader`·`dataBody` 형식을 쓰며 `access_token`·`token_type`·`expires_in`을 반환합니다. 시크릿 저장·로그·자동 재발급은 없습니다. 토큰 보관과 갱신은 호출자 몫입니다.

국내 잔고 SSQM2952는 공식 KRX 행의 공백 통화와 정산수량 `ec_q`를 읽어 미결제 매수분을 보존합니다. 총건수·행건수가 어긋나면 거부합니다. SKQM3350은 통화가 있는 6행과 금액이 모두 0인 빈 패딩 4행을 구분합니다. SPQM2226 공식 표본은 보유 건수 1·`Record2=[]`·양수 평가액·다른 블록에 섞인 TSLA 데이터로 불완전합니다. 이를 빈 계좌로 간주하지 않으며 `SpecUnverifiedError`로 닫습니다. 정상 페이지는 행건수와 `nxt_key`를 검증하며, 문서에 정의되지 않은 `cn_f` 값은 추정하지 않습니다.

국내 주문 가격은 원 단위 정수 문자열, 미국 주문·취소 가격은 P4(최대 소수 4자리)·String(15)입니다. 미국 취소는 기존 원장 `frgn_ordr_prc_p6`의 값에서 불필요한 0을 제거해 P4로 정확히 표현할 때만 보내며 전체 미체결 잔량과 일치해야 합니다. 소수 5자리 이상인 값은 반올림하지 않고 거절합니다. 모든 주문·취소 요청 칸은 공식 문자열 길이를 전송 직전에 검사합니다. 넘는 값은 잘라 보내지 않습니다. 국내 취소 `crct_clsf=1 + 수량`은 공식 성공 JSON 근거이며 XLSX의 «일부정정» 설명과 충돌합니다. 값 2의 의미는 추정하지 않습니다. 취소 접수는 취소 완료 증거가 아닙니다.

미국 주문일의 시간대는 공식 설명이 없어 뉴욕 날짜 기본값과 명시적 `order_date`를 유지합니다. 소수점 보유는 공통 정수 수량 계약으로 거부합니다. 공식 표본은 [출처·해시](../tests/fixtures/kb/official/SOURCE.md)에 고정했고 고객·계좌·주문·키 식별값은 가짜입니다. **증권사 호출 0건. 모의 없음 — 첫 실호출은 리뷰·대표 승인 뒤 실계좌 조회 한 번**, 그 뒤 별도 승인된 1주 지정가·취소 대사입니다. 미국 보유 원본·연속 조회·한국/뉴욕 날짜 경계·소수 가격 입력 수락·국내 전체 잔량 취소는 실계좌 검증 전 미확인입니다.

근거: [KB 공식 표본 수정 팩](status/2026-10-08-pack-kb-official.md).
