## 키움 (2026-10-24)

`create_broker("kiwoom", ...)`은 기존 REST 어댑터를 저장 토큰·앱키로 만듭니다. 생성만으로 토큰을 발급하지 않습니다. 주문·취소 전송은 기존 `OrderSafety` 기본 dry-run으로 꺼져 있으며 이를 켜는 새 환경변수는 없습니다. `virtual=True`일 때 모의 호스트를 고릅니다. 국내 시장가·지정가 매수/매도를 매핑하며 시장가는 기존 세션 허용·원화 평가를 요구합니다. `Kiwoom.amend_order(AmendRequest(...))`로 국내 지정가 정정을 보내며 공통 SDK protocol에 정정 메서드를 추가하지 않습니다. 정정 접수는 새 주문번호를 반환하고 side/type은 미확정으로 남깁니다. 정정 원장의 원주문은 완전 체결 외에는 ‘모름’으로 남깁니다.

공식 고정본의 ka10095 하한가 `-85200`·ka10001 연중최저 `-91200`에 맞춰 가격 문자열의 `+`·`-`를 방향 표시로 읽고 절댓값을 사용합니다. 상·하한가가 현재가·기준가를 포함하는지 검증은 유지합니다. 수량에는 가격 부호 처리를 적용하지 않습니다.

같은 가격 변환은 미국 시세·호가·잔고의 매입/현재가·주문가·체결단가에도 적용됩니다. 공식 미국 usa20100 연중최저 `-164.2700`과 usa20101·ust21070·ust21050 예시를 고정했고, 음수 가격은 부호만 바꾼 파생 사례로 시험합니다. 기존에 거절하던 미국 하락 종목의 음수 가격을 이제 절댓값으로 읽으므로 해당 종목의 주문 경로도 열립니다. 미국 호출 한도·현금·정지 판정·주문 안전 게이트는 유지합니다.

국내 현금은 kt00001 `ord_alow_amt`, `entr`, `100stk_ord_alow_amt`, `d2_entra`의 최솟값이며 음수 현금은 0원입니다(공식 예시 12,550원). 종목·가격별 `orderable_quantity`는 kt00011 `min_ord_alowq`를 사용합니다. ka10075 평균 체결가는 양수인 `cntr_tot_amt / cntr_qty`만 사용합니다. kt00007 취소확인의 `ori_ord`·종목·KRX가 일치하고 원주문 수량=체결+확인취소+잔량일 때만 판정하며, 잔량 0인 취소는 `cancelled`입니다. 취소 접수만으로는 완료로 판정하지 않습니다.

원주문 수량이 양수이고 체결 수량=주문 수량·잔량=0이면 뒤따른 정정·취소 행의 글자와 관계없이 `filled`입니다. 부분 체결은 위 취소 수량 보존 규칙을 따르며, 뜻을 모르는 정정·취소 글자는 `unknown`으로 남깁니다.

옛 `experimental.kiwoom.get_balance`는 추정예탁자산을 현금으로 반환하던 오류 때문에 호출 전에 차단합니다. 정식 어댑터를 사용합니다. 1700~1702는 공식 유량 초과 오류이나 이 HEAD에 재시도 가능 거절 분류가 없어 기존 `BrokerRejectedError`를 유지합니다. 자동 재시도는 없습니다.

기존 `examples/kiwoom_mock_roundtrip.py`의 기본은 dry-run입니다. `--execute`여도 모의 키가 없거나 공백이면 ‘키 없음’, `missing_keys`, 종료코드 0으로 끝나며 클라이언트 생성도 없습니다. 이는 실행 생략이지 왕복 성공이 아닙니다. 주문·조회·취소 왕복은 가짜 응답으로 시험했습니다. 증권사 실제 호출은 하지 않았습니다. 모의 키 발급 뒤 실제 모의 왕복과 독립 검수가 필요합니다.

## LS (2026-10-08)

`brokers/ls.py`와 `create_broker("ls", ...)`에 등록되어 있으며 `experimental.ls`는 같은 모듈의 호환 경로입니다. 저장 토큰으로 기본 REST 클라이언트와 기존 자격별 TR 한도표를 사용합니다. 토큰 발급·갱신은 하지 않습니다.

실계좌 주문·취소는 `allow_live_orders=False`로 기본 잠금입니다. 기존 명시 해제 인자는 저장 실계좌 토큰과 계좌 일치 조회를 요구하고 이후 `OrderSafety`를 거칩니다. `LS_SPEC_VERIFIED`는 합성 모의 검증의 잠금이며 실계좌를 여는 스위치가 아닙니다. 모의 REST 주소는 미확인으로 비어 있고 실제 `virtual=True` 생성은 거절됩니다. 시험에서만 가짜 모의 주소를 씁니다.

공식 CSPAT00601·CSPAT00801은 실계좌 주식에 종목코드 또는 `A+종목코드`를 허용하고 모의에는 `A+종목코드`를 요구합니다. 실계좌는 6자리, 합성 모의 주문·취소는 `A+6자리`를 보냅니다. 성공으로 해석하는 코드라도 양수 `OrdNo`가 있어야 접수입니다. 공식 TR 가이드에는 `00039/00040`의 성공 정의가 없어 이 코드와 주문번호가 함께 와도 기존 `InvalidResponseError`로 접수 여부 확인 필요를 알립니다. 같은 `client_key`는 실패 후에도 보존되어 자동 재전송되지 않습니다.

`t0424`·`t0425`·`COSAQ00102`는 `tr_cont`·`tr_cont_key`로 여러 쪽을 이어 받고 국내 본문 CTS도 다음 요청에 전달합니다. 응답 머리글·CTS 불일치, 반복 키, 20쪽 초과는 부분 목록을 반환하지 않고 오류로 닫습니다. 미국 잔고 `COSOQ00201`의 이어받기는 이번 범위 밖으로 계속 잠겨 있습니다.

미국 지정가는 NYSE·NASDAQ과 USD를 명시합니다. COSAT00301 요청에는 날짜 필드가 없고 COSAQ00102 `OrdDt`만 8자리 주문일자를 요구합니다. 공식에 거래일·시간대 선택 규칙이 없어 주문 전의 명시적 증권사 기준 `order_date` 잠금을 유지합니다. `fill_price`는 계속 `None`이며 실시간·정정·예약·통합증거금은 확장하지 않습니다. 모든 응답 fixture는 합성이고 증권사 호출은 0건입니다.

## NH (2026-10-08)

`create_broker("nh", ...)`는 저장 토큰 또는 앱키·시크릿으로 생성합니다. 계좌 종류 `acct_type`은 모의 `03`, 실계좌 `01`/`02`를 명시해야 합니다. 생성 직후 주입 클라이언트의 호스트도 검사합니다. 모의 주문·취소와 계좌 조회는 moapi, 토큰·계좌 확인·시세·규칙표는 api 호스트를 씁니다. 시세 운영 전용은 공식 명세 표시이며 실제 API 응답 확인 전 **UNVERIFIED**입니다.

`client_options`의 `brand`는 공식 SDK 식별자 `nhplug`(나무, 기본) / `n2plug`(N2)입니다. factory의 `PYKBROKER_CLIENT_OPTIONS`에도 같은 옵션을 넣습니다. 허용 주소는 `https://api.nhplug.com:8443`, `https://moapi.nhplug.com:8443`, `https://api.n2plug.com:8443`, `https://moapi.n2plug.com:8443` 네 곳이며 인증·조회·주문은 같은 브랜드를 사용합니다. 다른 주소·포트·브랜드는 생성 때 거절합니다.

국내 주문 가능 현금은 예수금 `dca`와 주문 가능 금액(`orr_pbl_amt4` 100% 기준 또는 구 필드 `orr_pbl_amt`)이 함께 있어야 확인됩니다. 현금은 응답에 있는 이 값들 모두의 최솟값입니다. 예수금이나 주문 가능 금액이 없거나, 있는 값이 잘못됐으면 실패합니다. 30%·40% 기준 금액은 쓰지 않습니다. **모의 응답으로 확정 전**입니다. 오늘 주문은 `Output_0` 또는 기존 `Output_1` 한 블록만 있으면 그것을 쓰고, 둘 다 있으면 내용이 같을 때만 `Output_0`을 씁니다. 한쪽만 빈 배열인 경우를 포함해 두 블록이 다르면 목록·상태 조회·이어받기 모두 확인 실패로 닫힙니다.

미국은 명시 `market="US", venue="US"`의 지정가·단일 취소·원장 조회를 구현합니다. 공식 국가 `200`·호가 `00`·센트 단가를 쓰며 매수만 `wtm_cur_knd_cd=1`을 보냅니다. 주문과 내역은 같은 `orr_no`를 `us:`로 보관합니다. `cns_pr`의 평균 여부는 미확인이라 평균 체결가는 모름입니다. 미국 모의 지원·실제 야간 주문일자는 확인하지 않았습니다.

실계좌 주문·취소는 `allow_live_orders=False` 기본 잠금입니다. `OrderSafety`나 MCP 주문 한도만 켜도 NH 실주문은 열리지 않습니다. 명시 해제 인자는 주문번호·원장번호 연결 검증과 별도 승인 뒤에만 사용해야 하며, 해제 후에도 기존 안전 게이트를 거칩니다. 계좌 소유 확인(`verify_account`)의 필수 적용은 주문번호·원장번호 연결 검증 때 함께 다룹니다.

계좌 모드 `virtual`은 읽기 전용이며 생성 때 검사한 주문 호스트로 잠금과 주문 표시를 판정합니다. 읽기는 알려진 정상 코드와 필수 데이터 블록으로 판정하고 완료 실패 문구를 거부합니다. `13578` 응답의 블록 없는 보유·일별 주문 내역은 빈 목록이며 매도가능 수량은 0입니다. 현금 조회는 요약 블록이 필요합니다. 모르는 코드는 완료 문구가 있어도 거부합니다. 손상된 공유 토큰 만료는 무시하고 새 토큰으로 덮으며 더 최신인 공유 토큰은 보존·재사용합니다. HTTP 리다이렉트는 따라가지 않습니다. 주문 응답 `mkt:`와 원장 `itg:`의 연결은 아직 없어 주문 직후 상태는 모름입니다.

## KB (2026-10-08)

`brokers.kb.KB`는 등록된 KR/US REST 어댑터입니다. 쓰기는 `writes_enabled=False`와 기존 `OrderSafety`로 기본 잠금이며 모의 API는 없습니다. 생성은 저장 토큰을 사용하고, `KB.issue_token(app_key=..., secret_key=...)`를 명시적으로 호출할 때만 Client Credentials 토큰을 발급합니다. 공식 `token.json`과 GitHub Python 예제의 `dataHeader`·`dataBody` 형식을 쓰며 `access_token`·`token_type`·`expires_in`을 반환합니다. 시크릿 저장·로그·자동 재발급은 없습니다. 토큰 전송·응답 오류는 except 밖에서 던져 원래 예외의 `__context__`·`__cause__` 고리를 남기지 않습니다. 토큰 보관과 갱신은 호출자 몫입니다.

국내 잔고 SSQM2952는 공식 XLSX에 수량 칸 이름만 있고 계산식이 없어 보유·미결제 매수·미결제 매도·정산·주문 가능 수량(각 P6 포함) 중 하나라도 0이 아니거나 행 평가액이 양수이면 `SpecUnverifiedError`(확인 필요)로 닫습니다. 공식 표본도 이 조건에 해당합니다. 오늘 거래가 없는 기존 보유를 조용히 빼거나 주문 가능 수량을 추정하지 않습니다. 총건수·행건수가 어긋나면 거부합니다. SKQM3350은 통화가 있는 6행과 금액이 모두 0인 빈 패딩 4행을 구분합니다. SPQM2226 공식 표본은 보유 건수 1·`Record2=[]`·양수 평가액·다른 블록에 섞인 TSLA 데이터로 불완전합니다. 건수 0으로 변형되어도 평가액이 양수이거나 다른 블록에 종목 흔적이 있으면 이를 빈 계좌로 간주하지 않으며 `SpecUnverifiedError`로 닫습니다. 정상 페이지는 행건수와 `nxt_key`를 검증하며, 문서에 정의되지 않은 `cn_f` 값은 추정하지 않습니다.

국내 주문 가격은 원 단위 정수 문자열, 미국 주문·취소 가격은 P4(최대 소수 4자리)·String(15)입니다. 미국 취소는 기존 원장 `frgn_ordr_prc_p6`의 값에서 불필요한 0을 제거해 P4로 정확히 표현할 때만 보내며 전체 미체결 잔량과 일치해야 합니다. 소수 5자리 이상인 값은 반올림하지 않고 거절합니다. 모든 주문·취소 요청 칸은 공식 문자열 길이를 전송 직전에 검사합니다. 넘는 값은 잘라 보내지 않습니다. 국내 취소 `crct_clsf=1 + 수량`은 공식 성공 JSON 근거이며 XLSX의 «일부정정» 설명과 충돌합니다. 값 2의 의미는 추정하지 않습니다. 취소 접수는 취소 완료 증거가 아닙니다.

미국 주문일의 시간대는 공식 설명이 없어 뉴욕 날짜 기본값과 명시적 `order_date`를 유지합니다. 소수점 보유는 공통 정수 수량 계약으로 거부합니다. 공식 표본은 [출처·해시](../tests/fixtures/kb/official/SOURCE.md)에 고정했고 고객·계좌·주문·키 식별값은 가짜입니다. **증권사 호출 0건. 모의 없음 — 첫 실호출은 리뷰·대표 승인 뒤 실계좌 조회 한 번**, 그 뒤 별도 승인된 1주 지정가·취소 대사입니다. 미국 보유 원본·연속 조회·한국/뉴욕 날짜 경계·소수 가격 입력 수락·국내 전체 잔량 취소는 실계좌 검증 전 미확인입니다.
