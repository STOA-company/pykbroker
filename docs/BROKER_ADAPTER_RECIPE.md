# Adding a broker adapter

## 1. 계약과 증거

`base.py`와 `models/`의 계약을 먼저 읽습니다. 조회·주문·취소에 필요한 공식 응답과 호출 방법을 확인하고, 사용한 문서 버전과 fixture 출처를 기록합니다. mock 응답과 벤더에서 녹화한 응답은 명확히 구분합니다. 모르는 필드나 기능을 성공값·0으로 대체하지 않습니다.

## 2. 주입 경계

어댑터는 `BaseBroker`를 상속하고 벤더 호출·모델 변환만 구현합니다. 계좌 선택은 생성자에서 전달받은 값만 사용합니다. 로거는 표준 logging을 사용하며 요청 본문·인증값·계좌 실값은 기록하지 않습니다. 인증·토큰 갱신·DB 접근이 필요하면 클라이언트나 콜백을 받습니다. SDK import는 연결이 필요한 시점까지 지연합니다.

## 3. 안전 게이트

공개 `place_order`·`cancel_order`를 통해 `OrderSafety`를 거친 뒤 `_place_order`·`_cancel_order`를 호출합니다. 주문 재시도나 수량 축소 루프를 추가하지 않습니다. 취소 요청을 종목 전체로 확대하지 않습니다. 네이티브 취소 범위를 확인하지 못하면 미지원으로 남깁니다.

미검증 어댑터는 `experimental/`에 두고 모듈의 `*_SPEC_VERIFIED = False`를 유지합니다. 공개 주문 메서드는 값이 정확히 `True`일 때만 다음 단계로 갑니다. 미확인 열거값은 caller `codes`로 주입되기 전까지 오류로 처리합니다. 잠금만 바꾸는 것으로 미확인 요청이 전송되어서는 안 됩니다.

BS-17 예외(2026-10-01 재발주): 대표 발주서가 상세 문서 접근 실패로 작업을 멈추지 말고
기존 LS 코드와 `UNVERIFIED` 표시로 진행하도록 지시했습니다. 따라서 LS는 `brokers/ls.py`
및 factory에 승격하되 `LS_SPEC_VERIFIED=False`와 기본 꺼짐 capability를 유지합니다.
정식 경로 등록과 실제 거래 지원을 구분하며, 미확인 코드에는 기본값을 넣지 않습니다.

## 4. 수명과 응답

동기 SDK는 인스턴스 종료 시 소유한 클라이언트를 정리합니다. 주입받은 클라이언트의 수명은 호출자가 관리합니다. async SDK는 생성·호출·종료를 하나의 이벤트 루프에 묶고 겹치는 사용을 방지합니다. 요청별 새 루프는 사용하지 않습니다.

잔고는 통화를 분리합니다. 미체결 목록 부재는 체결 증거가 아닙니다. 불명확한 주문 응답에는 `InvalidResponseError` 또는 `unknown` 상태를 사용합니다. 페이지 일부가 실패하면 부분 잔고를 전체 잔고로 반환하지 않습니다.

## 5. 검증

`tests/conftest.py`의 JSON fixture 로더와 네트워크 금지 fixture를 사용합니다. 최소 검증은 시세·빈 호가·누락 현금·페이지 실패·정확한 매수/매도 인자·취소 범위·드라이런 차단·중복 제출·한도 경계·SDK 미설치 import·종료입니다.

잠금 제거, 매수/매도 코드 교환, limiter 우회 같은 변이가 테스트 실패를 일으키는지 확인합니다. 검증 후 지원 표와 capability를 함께 갱신합니다. 라이브 거래 검증은 이 오프라인 테스트 스위트에 넣지 않습니다.

## 6. 공개 전 확인

소스·문서·예제에 비밀값, 회사별 주소, 계좌 저장 스키마가 없는지 검사합니다. 라이선스와 NOTICE를 검토하고, 실제 실행한 검증만 기록합니다. 미완료 항목은 TODO와 지원 표에 남깁니다.
